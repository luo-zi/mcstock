# MC 股市界面说明书（策划版）

> **这份文档讲什么**：界面上每一样东西「归哪个数字管」，以及「这个数字是怎么来的」。
> 不用懂代码——每个概念先用一句人话讲清楚，再告诉你它的名字。
>
> **详细的常量清单在附录里**：全部 170 多个常量、精确公式、代码行号，都在
> [`docs/UI_GUIDE_REF.md`](UI_GUIDE_REF.md)。这份主文档只讲**你真正会想改的那几十个**。
>
> **一句话记住规则**：界面上没有任何一个位置是写死的。每次打开界面、每次改窗口大小，
> 它都从「屏幕多大」重新算一遍。所以你只要改对**源头那几个数**，下游全部自动跟着走。
>
> 本文所有数字都是拿当前代码真跑出来的（`python tools\layout_dump.py 640 360`），不是手抄的。

## 第一节　界面是怎么一层层算出来的

### 先打个比方：这是一间「按比例盖的房子」

把它当成装修：

1. 先量**地块**——你的游戏窗口有多大；
2. 在地块上盖一间**房子**（面板）：占地块 88%，但不能太大也不能太小，盖在正中间；
3. 房子里隔出**玄关**（标题栏）、**门牌位**（三个页签）、**客厅**（内容区）；
4. 客厅再隔成**三间**：左边放企业卡、中间放走势图、右边放操作按钮；
5. 中间那间再上下切两刀：上面是**走势图**，下面是**持仓表格**；
6. 右边那间从上往下码**五块**：买入、卖出、数量、杠杆、资金情况；
7. 最后才轮到每块内部：卡片里的图标摆哪、表格六列各多宽、图里哪儿是柱子哪儿是刻度。

**关键点**：第 3 步往后，每一步只依赖**上一层算出来的框**，不依赖屏幕。
所以你把房子改大改小，屋里所有隔断会自动重排，不会错位。

### 先说单位：这里说的都是「逻辑像素」

Minecraft 会把窗口按「GUI 缩放」换算成一个固定坐标系再画界面。
同样是 1080p 全屏，GUI 缩放 3 就是 640×360，缩放 4 就是 480×270。
**本文里所有数字都是这个逻辑像素**，不是显示器像素。所以 2K 屏和 1080p 屏上，
同一个数字在物理尺寸上看起来一样大——这也是为什么不能按「屏占比」调，要按「放不放得下 6 位数字」调。

### 第 1 层　屏幕有多大

这是**唯一的输入**。代码里叫「屏幕逻辑宽 / 高」，界面上看不到它，但后面所有数字都从它出发。
换窗口大小、改 GUI 缩放，它都变，**一变整块界面重算**。

### 第 2 层　房子占多大、盖在哪

| 用到的数 | 它是什么 | 现在是多少 |
|---|---|---|
| `PANEL_W_RATIO`（面板宽度占屏幕的比例） | 房子宽度想占屏幕的百分之多少 | 0.88（88%） |
| `PANEL_H_RATIO`（面板高度占屏幕的比例） | 同上，管高度 | 0.88 |
| `PANEL_MIN_W` / `PANEL_MIN_H`（面板最小宽 / 高） | 房子再小不能小于多少 | 320 / 200 |
| `PANEL_MAX_W` / `PANEL_MAX_H`（面板最大宽 / 高） | 房子再大不能大于多少 | 720 / 440 |
| `PANEL_SCREEN_MARGIN`（面板离屏幕边的留白） | 房子离屏幕边缘至少留多少，免得贴边 | 6 |

宽度是「三步夹一下」算出来的：

1. 想占多少：`屏幕宽 × 88%`；
2. 天花板：`屏幕宽 − 6×2` 与 `720` 取小的那个；
3. 把第 1 步的结果夹在「地板」与「天花板」之间。

高度同理。**注意：高度的地板不是 `PANEL_MIN_H`（200），而是一个更大的数。**

> **为什么高度有个更高的地板？**
> 因为回收页必须放下「回收栏 + 合计块 + 回收按钮 + 背包 + 快捷栏」，
> 反推出来至少要 242 像素高。这个数叫 `MIN_PANEL_HEIGHT`（面板实际最小高度），
> 它是**算出来的**，不是手写的——想改它得动回收页那些常量。
> 屏幕矮到连 242 都放不下时，房子会退到屏幕允许的最高值：宁可裁掉底部，也不让块互相压。

**居中**：房子左上角 = `((屏幕宽 − 房子宽) ÷ 2, (屏幕高 − 房子高) ÷ 2)`，整除、小数点后丢掉。

**牵连**：房子一变，**下面所有东西**（玄关、门牌、客厅、三间屋、图、表、网格）全部重算。

### 第 3 层　玄关、门牌、客厅

在房子里从上往下切三刀：

**① 玄关 = 标题栏**，高 `TITLE_H`（标题栏高度）= 18。

- 里面右上角两个小方块：「关闭 ✕」和「帮助 ?」。边长 `CLOSE_SIZE`（按钮边长）= 12；
  离顶 `CLOSE_Y_PAD` = 3、离右 `CLOSE_X_PAD` = 4；帮助按钮在关闭按钮**左边**，中间隔 `HELP_CLOSE_GAP` = 6。
- ⚠️ 标题栏那个**倒计时**是贴着「帮助按钮左边再让 8 像素」放的。所以你把
  `HELP_CLOSE_GAP` 或 `CLOSE_X_PAD` 改大，倒计时会跟着往左挪。
- **牵连**：`TITLE_H` 一大，**下面所有东西整体下移**。

**② 门牌位 = 页签行**，高 `TAB_H`（页签高度）= 16。

- 单个页签宽度 = `房子宽 ÷ 6`，夹在 `TAB_MIN_W` = 64 与 `TAB_MAX_W` = 160 之间。
  三个横排，中间隔 `TAB_GAP` = 4，三个**整体居中**。
- **牵连**：`TAB_H` 一大，**客厅整体下移**。

**③ 客厅 = 内容区**，三个页面共用的舞台。

- 上边紧贴页签下沿——中间的缝 `TAB_ROW_GAP` 与 `CONTENT_GAP` 现在**都是 0**，
  这是刻意做的（玩家要求「页签一结束就是图」）。
- 左右和底部各留 `CONTENT_PAD` = 8、`CONTENT_BOTTOM_PAD` = 8。
- 高度 = 房子底边往上 8 像素 − 客厅上边；算出来不到 40 就保底 40。

**④ 客厅最上面那 11 像素留给「状态提示」**，也就是 `FLASH_BAND_H`（状态提示带的高度）= 11。

- 买卖成功那类一闪而过的提示就出现在这一条带上，**平时是空白**。
- 这就是为什么图上沿与页签下沿数值相等，而左右两列却各低 11 像素：图故意往上顶进这条带
  （提示自带半透明底衬，浮在图区上沿那一小块留白上，不会糊住柱子）。
- **牵连**：`FLASH_BAND_H` 一大，**三个页面的所有内容整体下移**。

### 第 4 层　客厅隔成三间

| 这一刀 | 由哪个数决定 | 现在是多少 | 变了会连带什么 |
|---|---|---|---|
| 左列宽度 | `LEFT_COL_W`（左列宽度） | 64 | **中间那块反过来变宽**：中间左边界 = 左列右边 + 缝 |
| 左列与中间之间的缝 | `COL_GAP`（列间距） | 6 | 左列与中间一起动 |
| 右列宽度 | `RIGHT_COL_W`（右列宽度） | 100 | 右列从客厅右边往左量 100，**中间那块跟着变宽/变窄**。⚠️ 右列里「数量」那一行有硬性宽度要求，见第二节 |
| 中间那一块 | **剩下的全部** | 371（640×360 下） | 它没有自己的宽度常量：宽度 = 客厅右边 − 缝 − 中间左边界，最小保底 120 |

**关键**：三间是「左右钉死、中间吃剩下的」。
所以你改左列或右列宽度，**动到的是中间那块**，房子本身不会变。

### 第 5 层之一　中间那间：上下切两刀（走势图 / 持仓表格）

这两块**互相抢高度**，所以顺序很重要：先定表格多高，剩下的全给图。

1. **先算表格想多高**：`客厅可用高 ÷ 3`，再夹在
   `POS_TABLE_MIN_H` = 28（表头 + 1 行）与 `POS_TABLE_MAX_H` = 109（表头 + 6 行）之间。
2. **再看图能不能让**：图有两条底线——`CHART_MIN_H`（走势图最小高度）= 80，
   以及 `CHART_SLACK`（留给图的余量）= 40。能让给表格的 = `客厅可用高 − 80 − 40`。
   这个数比表格初值大，表格就加高（仍不超过 109）。
3. **保图**：加高之后图如果不足 80，就把表格压回去，让图正好 80。
4. **表格太小就整块不画**：算出来比「表头 + 1 行」= 27 还小，表格高度直接归 0，高度全给图。
   这时界面下方是光秃秃一片，**不是出 bug**。
5. **表格钉在客厅底部**；图上沿顶到客厅上沿；图下沿与表格上沿之间留 `POS_GAP`（图与表格之间的空隙）= 4。

**牵连**：`POS_ROW_H`（数据行高）一大，能显示的行数变少；
反过来图的高度完全由「客厅可用高 − 表格高 − 4」决定，所以**表格每多一行 16 像素，图就矮 16 像素**。

### 第 5 层之二　右列：从上往下码五块

右列是一根「按顺序往下摞」的柱子：

| 顺序 | 块 | 高度由谁定 | 现在是多少 | 与上一块的空隙 |
|---|---|---|---|---|
| 1 | 买入按钮 | `BTN_MAIN_H`（主按钮高度） | 24 | — |
| 2 | 卖出按钮 | 同上 | 24 | `BTN_GAP`（按钮之间的小空隙）= 3 |
| 3 | 数量行 | `FIELD_ROW_H`（填写行高度） | 20 | `BTN_GROUP_GAP`（组与组之间的大空隙）= 6 |
| 4 | 杠杆行 | 同上 | 20 | `BTN_GAP` = 3 |
| 5 | 资金情况块 | **吃掉剩下的全部高度** | 158（640×360 下） | `BTN_GROUP_GAP` = 6 |

**牵连**：上面任何一块变高，**资金块立刻变矮**（它是被挤的那个）。
资金块能画几行也是算出来的：`(块高 − 标题 12) ÷ 行高 13`，再夹在 1 与
`FUNDS_LINES`（资金块最多画几行）= 7 之间。

### 第 6 层　每个控件在自己格子里怎么放

前面五层只是在「划格子」。格子内部怎么摆，靠各自的小偏移量：

| 格子里 | 用它自己的小偏移 |
|---|---|
| 企业卡片 | 图标离左 6、离上 6（`CARD_ICON_OFF_X` / `CARD_ICON_OFF_Y`）；企业名离左 6、离上 27（`CARD_NAME_OFF_X` / `CARD_NAME_OFF_Y`）；右上角涨跌箭头离右 6（`CARD_ARROW_PAD_X`）、离上 7（`CARD_ARROW_OFF_Y`） |
| 走势图内部 | 外框往里缩 `CHART_INNER_PAD` = 4；企业名行高 11、现价行高 11（都是 `CHART_ROW_H`）；这两行与绘图区之间空 `CHART_HEADER_GAP` = 2 |
| 走势图里再分左右 | 右边切出 `CHART_AXIS_W`（价格刻度带宽度）= 46 给价签和刻度，**左边剩下的才是柱子地盘**。两块不许互相越界（实机出过「数字挡住柱子」） |
| 持仓表格 | 表头行高 `POS_TITLE_H` = 11；数据行高 `POS_ROW_H` = 16；六列按固定比例分（见第三节）；行尾一个「平」按钮宽 `POS_CLOSE_W` = 22，**不参与压缩**；最右边留 3 像素给滚动条 |
| 数量 / 杠杆行 | 一行五个小格：标签 12 → 空 2 → 数字框 42 → 空 2 → ▲ 11 → ▼ 11 → 空 2 → MAX 14，加起来 96，正好塞进右列的 100 |
| 购买页网格 | 每格边长 `SLOT`（格子边长）= 18，从网格左上角按行列铺开 |

**收尾**：回收页那些块算完之后，还会统一做一次「不许出框、不许互相压」的检查——
装不下的块会被静默丢掉，能折的就折。这是第四节第 ① 条的主角。

## 第二节　什么东西管什么

> 每行一句话，格式是：**我想改… → 动这个数字 → 它还会牵连什么**。
> 加 ⚠️ 的是「改了容易踩坑」的。这一节只列你会想改的，其余 170 多个常量见附录。

### 面板与整体

| 我想改… | 动这个数字 | 它还会牵连什么 |
|---|---|---|
| 面板占屏幕多大 / 摆在哪儿 | `PANEL_W_RATIO` / `PANEL_H_RATIO`（0.88 / 0.88）；位置永远是**居中**，没有独立常量 | 比例一改，**一切**都从它推出来：三列、图表、表格、网格全部重排。想不居中只能改「居中」那条算式 |
| 面板最大能多大 / 离屏幕边留多少 | `PANEL_MAX_W` / `PANEL_MAX_H`（720 / 440）、`PANEL_SCREEN_MARGIN`（6） | 两个数一起决定天花板：面板宽最多 = min(720, 屏幕宽 − 12)。大屏上面板不再变大，字号和格子不会跟着放大，只是留白变多 |
| 面板最小能多小 / 上下的实际底线 | `PANEL_MIN_W` / `PANEL_MIN_H`（320 / 200）、`MIN_PANEL_HEIGHT`（242，算出来的） | 宽由前者说了算；**高度真正的底线是 242 而不是 200**，它由回收页反推，想改得动回收页那些常量 |
| 客厅四周留白 | `CONTENT_PAD` / `CONTENT_BOTTOM_PAD`（8 / 8） | 三个页面的可用区一起变，帮助面板的折行宽度也跟着变 |
| 状态提示带多高 | `FLASH_BAND_H`（11） | 三个页面的内容整体下移 |

### 标题栏

| 我想改… | 动这个数字 | 它还会牵连什么 |
|---|---|---|
| 标题栏多高 | `TITLE_H`（18） | 页签、客厅、整页内容全部下移 |
| 右上角两个按钮多大 | `CLOSE_SIZE`（12） | 关闭和帮助一起变，倒计时的右边界跟着挪 |
| 关闭按钮离右边 / 顶部多远 | `CLOSE_X_PAD`（4）/ `CLOSE_Y_PAD`（3） | 帮助按钮和倒计时跟着挪 |
| 帮助按钮离关闭按钮多远 | `HELP_CLOSE_GAP`（6） | 倒计时往左让位 |

### 页签

| 我想改… | 动这个数字 | 它还会牵连什么 |
|---|---|---|
| 页签多高 | `TAB_H`（16） | 客厅整体下移 |
| 页签多宽 | `房子宽 ÷ 6`，夹在 `TAB_MIN_W`（64）/ `TAB_MAX_W`（160） | 面板很宽时页签不再变宽，只在中间拉伸出更多空白 |
| 页签之间多宽 | `TAB_GAP`（4） | 三个页签整体居中，左端跟着挪 |
| 页签上下的缝 | `TAB_ROW_GAP` / `CONTENT_GAP`（都是 0） | ⚠️ 调大就会在页签和走势图之间露出一条空白（现在刻意是 0） |

### 左列卡片

| 我想改… | 动这个数字 | 它还会牵连什么 |
|---|---|---|
| 左列多宽 | `LEFT_COL_W`（64） | **中间那块图和表格跟着变宽**，房子不变 |
| 卡片多大 | `CARD_W`（56）/ `CARD_H`（44） | 卡片列不参与高度分配，所以卡片变高**不会挤到别人**，只是它自己更长 |
| 卡片之间隔多远 | `CARD_GAP`（6） | 三张卡总高变，左列下方空白变 |
| 卡片里图标的位置 | `CARD_ICON_OFF_X` / `CARD_ICON_OFF_Y`（6 / 6） | 只影响卡片内部 |
| 卡片里企业名的位置 | `CARD_NAME_OFF_X` / `CARD_NAME_OFF_Y`（6 / 27） | 名字可用宽度跟着卡片宽缩 |
| 卡片右上角涨跌箭头 | `CARD_ARROW_PAD_X`（6，离右边）/ `CARD_ARROW_OFF_Y`（7，离顶） | 只影响卡片内部 |
| 卡片下面那块「市场指数」小结 | `INDEX_TOP_GAP`（8，离最后一张卡多远）/ `INDEX_LINE_H`（11，一行多高）/ `INDEX_LINES`（**3**：标题 / 指数值 / 中性氛围词） | 块高 = 行高 × 行数，再夹进「卡片下沿 → 左列下沿」的剩余空间；放不下就少画几行、**一行都放不下整块不画**（卡片不受影响）。⚠️ 这里**没有涨跌行、也没有「牛市/熊市」**：界面不替玩家下买卖判断 |

### 走势图

| 我想改… | 动这个数字 | 它还会牵连什么 |
|---|---|---|
| 走势图最低多高 | `CHART_MIN_H`（80） | 表格最多只能长到「客厅可用高 − 80」 |
| 图给表格让位时留多少余量 | `CHART_SLACK`（40） | 数字调大 = 图更宽裕、表格更矮 |
| 图的外框与里面那块之间留多少 | `CHART_INNER_PAD`（4） | 绘图区、表头行、现价行一起往外/往里挪 |
| 图内「企业名」「现价」两行多高 | `CHART_ROW_H`（11） | 两行一起变，**绘图区反向变高** |
| 两行与绘图区之间的缝 | `CHART_HEADER_GAP`（2） | 同上 |
| 图与表格之间的缝 | `POS_GAP`（4） | 表格跟着上下挪 |
| 右边价格刻度带多宽 | `CHART_AXIS_W`（46） | **柱子地盘反向变化**；窗很窄时最多占一半 |
| 一根柱子多宽 / 圆角 / 一屏几根 | `CANDLE_PX`（7）/ `CANDLE_RADIUS`（2）/ `CANDLE_MIN` 、`CANDLE_MAX`（20 / 60） | 一屏根数 = 柱子地盘宽 ÷ 7 再夹在 20~60；柱子矮于 3 像素时圆角自动退化成方角 |
| 一根柱子代表多久 | `CANDLE_TICKS`（5 跳 = 10 秒） | 只改时间尺度，不改布局 |
| 涨跌用什么颜色 | `COLOR_UP`（涨，红）/ `COLOR_DOWN`（跌，绿） | 柱子、方向字、盈亏、箭头、现价虚线全跟着变；**两个值对调就是欧美口径（绿涨红跌）** |
| 现价虚线 / 爆仓虚线 | 没有布局常量 | 颜色跟着涨跌；爆仓虚线**只在刻度范围内才画**，超出量程改成边缘一个小三角 + 一行字 |
| 三个价格刻度与价签 | 没有布局常量 | 都挤在刻度带里；三个刻度一直画，但**现价价签和爆仓价文字**如果跟已有文字离得太近（不足 11 像素）会**整个不画**，免得糊在一起 |
| 新闻条（表头行右边那条黄色滚动字幕）走多快 | `NEWS_SCROLL_SPEED`（1 像素/tick = 20 像素/秒） | **只影响滚动速度，不改变位置**：一圈耗时 = （新闻条宽 + 文字宽）÷ 速度。改它不会动任何矩形 |

## 第三节　拿 640×360 走一遍

> 这一节是「怎么来的」最直观的答案：从屏幕 640×360 出发，一步一步算出每一个框。
> **下面每个数字都实跑过 `python tools\layout_dump.py 640 360` 核对**，不是手算的。
> 640×360 就是「1080p 全屏 + GUI 缩放自动」下最常见的逻辑分辨率。

### 第 1 步　面板宽度

```text
天花板 = min(720, 640 − 6×2) = min(720, 628) = 628
想占的 = 640 × 88% = 563.2 → 四舍五入 = 563
地板   = min(320, 628) = 320
面板宽 = 把 563 夹在 320 和 628 之间 = 563
```

### 第 2 步　面板高度

```text
天花板 = min(440, 360 − 6×2) = min(440, 348) = 348
想占的 = 360 × 88% = 316.8 → 四舍五入 = 317
地板   = min(242, 348) = 242          ← 242 就是 MIN_PANEL_HEIGHT
面板高 = 把 317 夹在 242 和 348 之间 = 317
```

顺带把那个 242 拆开，它是回收页反推出来的：

```text
标题栏 18 + 页签行 16 + 客厅内容 200 + 客厅下留白 8 = 242
那 200 = 回收栏上边空 4 + 回收栏 2 行 36 + (合计块 2 行 26 + 缝 8 + 回收按钮 28 = 62)
        + 按钮与明细之间 4 + 明细最少 0 + 明细与背包之间 4
        + 背包标签 12 + 背包 54 + 缝 6 + 快捷栏 18
```

### 第 3 步　面板放哪（居中）

```text
左 = (640 − 563) ÷ 2 = 77 ÷ 2 = 38     ← 整除，那 0.5 像素直接丢掉
上 = (360 − 317) ÷ 2 = 43 ÷ 2 = 21
面板 = 左上角 (38, 21)，大小 563 × 317，右边界 601，下边界 338
```

### 第 4 步　标题栏与两个按钮

```text
标题栏高 = 18
标题栏 = (38, 21, 563, 18)，下沿 y = 21 + 18 = 39

关闭按钮 x = 38 + 563 − 4 − 12 = 585
关闭按钮 y = 21 + 3 = 24
关闭按钮 = (585, 24, 12, 12)

帮助按钮 x = 585 − 6 − 12 = 567
帮助按钮 = (567, 24, 12, 12)          ← 在关闭按钮左边
倒计时右端 = 567 − 8 = 559            ← 贴着帮助按钮再让 8 像素
```

### 第 5 步　页签行

```text
单个页签宽 = 563 ÷ 6 = 93（整除），夹在 64~160 之间 → 93
三个 + 两个缝 = 93×3 + 4×2 = 279 + 8 = 287
左端 x = 38 + (563 − 287) ÷ 2 = 38 + 276 ÷ 2 = 38 + 138 = 176
页签 y = 21 + 18 + 0 = 39

第 1 个页签 = (176, 39, 93, 16)
第 2 个页签 = (176 + 93 + 4 = 273, 39, 93, 16)
第 3 个页签 = (273 + 93 + 4 = 370, 39, 93, 16)
```

### 第 6 步　客厅（内容区）

```text
客厅上沿 y = 39 + 16 + 0 = 55         ← 与页签下沿数值相等（中间两道缝都是 0）
客厅左   x = 38 + 8 = 46
客厅宽   = 563 − 8×2 = 547
客厅高   = max(40, 21 + 317 − 8 − 55) = max(40, 275) = 275

客厅 = (46, 55, 547, 275)，右边界 593，下边界 330
状态提示带 = 客厅最上面那 11 像素
页面内容起点 = 55 + 11 = 66
页面可用高   = 275 − 11 = 264
```

### 第 7 步　三列

```text
左列 = (46, 66, 64, 264)                        ← 宽 = LEFT_COL_W = 64

右列宽 = 100
右列 x = 593 − 100 = 493
右列 = (493, 66, 100, 264)

中间 x = 左列右边 110 + 缝 6 = 116
中间宽 = max(120, 493 − 6 − 116) = max(120, 371) = 371
```

### 第 8 步　左列三张卡片

```text
卡片0 = (46, 66, 56, 44)
卡片1 = (46, 66 + 44 + 6 = 116, 56, 44)
卡片2 = (46, 116 + 44 + 6 = 166, 56, 44)

三张卡总高 = 44×3 + 6×2 = 144
左列有 264 高 → 卡片下方还剩 264 − 144 = 120 像素是空的
（卡片列不参与高度分配，这些空白不会被别的块拿走）
```

### 第 9 步　中间：先定表格高度

```text
表格初值 = 264 ÷ 3 = 88，夹在 28~109 之间 → 88
图能让出的 = 264 − 80（图最低）− 40（给图的余量）= 144
144 > 28，所以表格加高：把 max(88, 144) = 144 夹在 28~109 → 109
复查：图还剩 264 − 109 = 155 ≥ 80，通过
      109 ≥ 11 + 16 = 27，不用整块丢掉

表格 = (116, 66 + 264 − 109 = 221, 371, 109)，下沿 = 330（正好是客厅下边界）
```

### 第 10 步　走势图外框

```text

图上沿 y = 66 − 11 = 55                 ← 故意往顶进提示带 11 像素

走势图 = (116, 55, 371, 162)，下沿 y = 217
核对：表格上沿 221 − 图下沿 217 = 4 = POS_GAP ✓
```

### 第 11 步　走势图里再切四段

```text
一屏柱子根数（脚本里那个数）= 363 ÷ 7 = 51，夹在 20~60 → 51
⚠️ 但真正画出来的是按柱子地盘算的：317 ÷ 7 = 45 根
```

| 购买页 | 分类按钮 (46, 66, 84, 18)；搜索框 (136, 66, 365, 18)；◀ (507, 66, 18, 18)；页码 (527, 66, 46, 18)；▶ (575, 66, 18, 18)；网格 (139, 90, 360, 144) = **20 列 × 8 行 = 一页 160 格**；背包 (238, 252, 162, 54)；快捷栏 (238, 312, 162, 18) |

### 换个窗口尺寸会怎样

同一套算式在别的逻辑分辨率下的结果（也是实跑值）：

| 逻辑分辨率 | 面板 | 走势图 | 表格行数 | 网格 | 资金块行数 | 回收页 |
|---|---|---|---|---|---|---|
| 640×360（典型） | 563×317 | 371×162 | 6 | 20×8 | 7 | 2 行栏 + 合计块 + 明细 7 行 |
| 854×480 | 720×422 | 528×267 | 6 | 20×13 | 7 | 2 行栏 + 合计块 + 明细 15 行 |
| 1920×1080 | 720×440（顶到上限） | 528×285 | 6 | 20×14 | 7 | 2 行栏 + 合计块 + 明细 16 行 |
| 427×240（小窗） | 376×228 | 184×124 | 2 | 20×3 | 4 | **1 行栏 + 无合计块** + 明细 4 行 |
| 320×240 | 308×228 | 120×124 | 2 | 16×3 | 4 | **1 行栏 + 无合计块** + 明细 4 行 |
| 213×120（极端） | 201×108 | 120×80 | **0（整块不画）** | 10×1 | 1 | 1 行栏 + 无合计块 + **无明细** |

看这张表能读出两件事：
**① 面板到 720×440 就封顶了**，所以 1080p 和 4K 看到的界面一样大，只是周围留白更多；
**② 小窗口下回收页会自己降级**（栏折一行、合计块丢掉），这就是第四节第 ① 条说的事。

## 第四节　改的时候看这三件事

### ① 会挤到别人：界面会「按优先级丢块」

这个界面不是「算好就画」，而是**先满足必须的块，装不下就按优先级丢块**。
回收页是最明显的例子。

**必须先画出来的三样**（永远不丢）：回收栏、背包、回收按钮。
玩家要靠 shift 点背包往回收栏放东西，没了背包这一页就没法玩。

**其余按这个优先级保**：

```text
明细列表（有明细 +100 分）
  > 合计块（+10 分）
    > 回收栏保持 2 行（+1 分）
```

所以为了保住明细，程序宁可**把回收栏折成 1 行、把合计块整块丢掉**。

> ⚠️ **别记成「先丢明细」**——实测是反过来的：**明细是最后才丢的**。
> 牺牲顺序是「合计块 → 回收栏第二行 → 明细」。原因很直白：明细是玩家看回收收益的地方，
> 合计块里的金额本来就会写进回收按钮的文案里，丢了也不心疼。

实测（640 宽逐像素扫高度）：

| 窗口高度 | 回收页实际变成什么 |
|---|---|
| 640×360 | 回收栏 2 行 + 合计块 + 明细 7 行（什么都全） |
| 640×250 | 回收栏 2 行 + 合计块 + 明细 **只剩 1 行**（刚好还保得住合计块） |
| 640×**249** | 立刻掉档：**回收栏折成 1 行 + 合计块整块不画**，换来明细 4 行 |
| 640×200 | 回收栏 1 行 + 无合计块 + 明细 1 行 |
| 640×180 | 回收栏 1 行 + 无合计块 + **明细也没了**（0 行） |

**这就是「改了没生效」的真相**：你改的那个块，可能已经被优先级丢掉了。
高度只差 1 像素就可能整套换掉（249 和 250 就是一条硬分界）。

别的页面也有同样的机制：

- **走势图**：不管怎么挤，图至少留 `CHART_MIN_H`（80）——被牺牲的是表格。
- **持仓表格**：算出来不到「表头 + 1 行」（27）就**整块不画**，把高度全让给图。
- **资金块**：上面每一块变高，它都变矮；行数从 7 一路压到 1。
- **购买页网格**：行数下限其实是 **1 行**（`GRID_MIN_ROWS` 写了 4 但没用上）。
- **回收明细**：余数会被丢掉，所以「只多几像素」不一定能多画一行。

**所以改完至少要跑 4~5 个窗口尺寸**，别只跑一个。
想知道某个块是不是被丢了：看它的宽度或高度**是不是变成了 0**。

### ② 别直接改「画东西的地方」

界面上**每一个位置都从布局表里取**，绘制的地方只是照着画。
如果你跳过布局、直接在绘制的地方把某个数字加上 10，当时看着对了，
**换个窗口大小就会错位**——因为布局重算了，你写死的那 10 像素没有跟着走。

正确的改法固定是这两步：

1. 想动**位置或大小** → 改布局那侧的常量（这份文档第二节列的就是它们）；
2. 想动**画什么、什么颜色、什么字** → 才去改绘制的地方。

判断办法很简单：如果这个数字跟「别的块在哪」有关，它就该是常量；
如果只跟「这块自己长什么样」有关（比如图标在卡片里偏移 6），才是局部的小偏移。

### ③ 文字要套现成的画字工具

**直接画字会「贴在框上沿、和旁边的字不在一条线」。**

原因：游戏的画字接口给的是**字模盒顶端**的坐标，而中文字体的行高比字本身高一点。
你拿「框的上边」当文字坐标，字就贴到上沿去了，下面空出一截，几行字之间也对不齐。

所以项目里准备了几个画字的小工具，都自动做了**框内垂直居中**：

| 工具 | 什么时候用 |
|---|---|
| 「矩形里画一行，左对齐」 | 绝大多数标题、标签 |
| 「矩形里画一行，可指定左 / 中 / 右」 | 居中的按钮文案、右对齐的金额 |
| 「矩形里画一行，自己给上下位置」 | 一个块里排多行（比如回收明细） |
| 「右对齐的一行」 | 靠右的金额、小计 |
| 「左对齐 + 放不下就裁尾」 | 窄窗口下的长名字（不画省略号，直接把多余的字去掉） |

还有一条配套规矩：**小号数字字体只能给数字和符号用**。
中文套上去会变成缺字方块（游戏在指定字体里找不到字形时不会自动回退）。
中文（企业名、多/空、列名）一律保持常规字号。

## 第五节　改完怎么自己看

### 命令一：打印数字（最快，不用开游戏）

```powershell
cd E:\mc_stock
python tools\layout_dump.py 640 360
```

**能看到什么**：面板、标题栏、客厅、左列、走势图外框、绘图区、右列、资金块、回收栏、网格的
矩形（x, y, 宽, 高），外加柱子根数和「一页几格」。
它跑的是**真正的布局代码**，所以打出来就是游戏里会用的值——不是另写一份公式。

**注意什么**：

- 它只打**摘要**。想看别的矩形（比如明细框、六列宽度、数量行五个小格），用这一行：

  ```powershell
  python -c "import sys;sys.path.insert(0,'tools');from layout_dump import dump;L=dump(640,360)['layout'];print('明细',L['barDetail'],L['detailLines'],'行');print('六列',[L['posCol%d'%i] for i in range(6)]);print('数量行',L['qtyLabel'],L['qtyField'],L['qtyUp'],L['qtyDown'],L['qtyMax'])"
  ```

- **改完至少抽查 4~5 个尺寸**（例如 640×360、640×249、640×250、427×240、213×120）。
  只跑一个尺寸很容易「改好了一个，弄坏了三个」。
- 它不启动游戏，第一次跑会先编译一次（多等一两秒），之后就走缓存。
- 跑完没报错、能看到上面那些行，就说明布局算式本身是通的。

### 命令二：出效果图（最直观，可以发给别人看）

```powershell
python tools\gen_gui_mockup.py 640 360 试改1
```

**能看到什么**：三个页面的整屏效果图，2 倍放大。

- `docs/gui_mockup_recycle.png` / `_trade.png` / `_shop.png` —— **固定路径，会被下一次覆盖**；
- `docs/review/试改1_gui_mockup_recycle.png` / `_trade.png` / `_shop.png` —— 带标签的副本，不会被覆盖。

**注意什么**：

- ⚠️ 文件名是 **「标签_文件名」**，标签在最前面：
  `试改1` ＋ `gui_mockup_trade.png` → `试改1_gui_mockup_trade.png`。
  **评审时贴带标签的那份**，别贴固定路径（聊天窗口会按路径缓存老图，你发的是新图、别人看到的是旧的）。
- 它读的是**同一份布局结果**，所以图上的位置和游戏里一致。
- ⚠️ **改了圆角或图标，效果图不会自己变**：圆角是**贴图里的透明像素**，
  得重跑贴图脚本（`python tools\gen_gui_textures.py`，跑完还要补一次
  `python tools\patch_close_help_sprites.py`，否则关闭按钮的 ✕ 会被冲淡成幽灵圈）。
- ⚠️ 改了小号数字字体的字号或字符集，要重跑字体脚本，否则字宽对不上、整行错位。

### 命令三：进游戏看真实效果（最终验收）

```powershell
.\gradlew.bat runClient
```

**能看到什么**：单机进世界，手持「交易所终端」右键开界面，就是玩家看到的样子。

**注意什么**：

- 进游戏后**随手把 GUI 缩放改一改**（设置 → 视频设置 → GUI 缩放），
  就能看到同一份布局在别的逻辑分辨率下的样子——比如缩放 4 会变成 480×270 那种小窗。
- **效果图不算验收**。字号、中文、图标到底放不放得下，只有真机截图能看出来
  （历史上有几次事故是「所有脚本都跑通了，只有真机上看得见问题」）。
- ⚠️ 改了语言键（新增/删除/改名文案）要跑一次校验脚本，差集必须为空：

  ```powershell
  python tools\check_lang_keys.py
  ```

### 一张小抄：改了什么 → 必须跑什么

| 你改了什么 | 必须跑 | 不跑会怎样 |
|---|---|---|
| 任何宽高 / 间距 / 位置常量 | 命令一（抽查多尺寸）＋ 命令二 | 效果图和文档还是旧布局，别人看的是你没改的东西 |
| 圆角半径 | 贴图脚本 + 补 ✕? 的脚本 | 圆角大小不变，只是切片被拉伸 |
| 图集里任何切片的位置或大小 | 同上 | 代码取的坐标和贴图上画的对不上 → 实机看到错位 |
| 小号数字字体 | 字体脚本 | 字宽对不上、光标错位 |
| 任何语言键 | 校验脚本 | 键差集不为空，直接报错退出 |
| 所有改动的收尾 | `.\gradlew.bat build` | 编译错误没人拦 |
