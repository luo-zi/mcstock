# 更新日志（MC 股市 / mcstock）

## 1.0.2

### 一、新成就「空中飞人」

- **怎么拿**：**欠着钱**（余额为负）从 **100 格以上**摔死（死因必须是摔落伤害）。
- **拿到之后**：**债务直接清零**（余额置 0），并弹一条聊天提示。
  这一摔反而把债摔干净了 —— 成就描述里就是这么写的。
- 成就框架是 `challenge`（挑战），有 Toast 与全服公告；图标是羽毛，放在成就界面的独立页签里。
- 判定边界：**刚好 100.0 格算达标**；余额 0 或正数不触发；没摔死（被水接住、图腾）不触发。

### 二、可买/可卖的物品补齐，重点是农作物

- **新增可买可卖**：小麦种子、甜菜种子、西瓜种子、南瓜种子（各 **1 金币**）、
  发光浆果（2）、海泡菜（2）、红蘑菇 / 棕蘑菇（各 2）、紫颂果（4）、
  蜂蜜瓶（5）、牛奶桶（30）。
- **价格调整**：南瓜 **2 → 4** —— 因为「1 南瓜 → 4 南瓜种子」，种子有价南瓜就必须 ≥ 4，
  否则买南瓜拆种子再卖就白赚。
- 西瓜 / 干海带 / 蜂蜜块 / 蘑菇煲 / 蛋糕这些**没有种子**，按配方推导出价
  （西瓜 9、干海带 1、蜂蜜块 20、蘑菇煲 4、蛋糕 99）。
- **购买页因此多出 11 条**（8 个此前无价的物品 + 3 个因新价而变得可推导的产物）。
- 全部条目都在「可再生 ≤ 30」规则内；「买原料 → 做产物 → 回收」已逐条验算**不会白赚**。

## 一、两个掉线 bug（线上事故，已修）

### 1. 物品目录太大 → 一进服就掉线

- **现象**：装了大型整合包时，打开股市终端（或在登录时收到目录）**直接掉线**，
  客户端报 `Failed to decode packet`。
- **原因**：能推得出估价的物品有 **7799 件**，而原来把**整份目录塞进一个包**。
  原版解码端对数组长度有 **4096** 的上限，超了就抛异常 —— 一抛就是掉线。
- **修法**：
  - 目录改成**分片下发**：每片最多 **1024 条**，7799 条 → **8 片**，每片约 2KB；
  - 客户端**累积分片、收齐才整体替换**（没收齐之前保持旧目录，不会搜到一半看到残缺列表）；
  - 协议版本号 `3 → 4`（片头多了 `part` / `totalParts`）；
  - 解码端统一走 `PacketGuards`：**声明长度超上限不再抛，改为夹住 + 去重告警**。
- **影响面**：所有装了大型整合包的玩家。修完 7799 件的整合包也能正常进。

### 2. 提示行的字符串读取上限不一致 → **只要提示非空就必掉**

- **现象**：**任何一条非空提示**（买卖成交、回收、余额不足…）都会让客户端掉线，
  报 `The received encoded string buffer length is longer than maximum allowed (103 > 102)`。
- **原因**：**写端与读端用了两个不同的上限**。写端 `writeUtf` 本身不带上限
  （最多 32767 字符），读端却按一个更小的数去读。上一条提示只要超过那个数就必炸。
  雪上加霜的是读端实现有 bug：调了会**自己再读一次长度前缀**的 API，于是报出的
  「103 > 102」这个数字完全对不上真实长度，极难排查。
- **修法**：
  - 读端**自己读长度、自己切字节**，长度荒谬就夹住 + 去重告警，**绝不抛异常**；
  - 写端**先按码点截断**再写，保证「写出去的内容永远不超过读端允许的上限」；
  - 读写**共用同一个常量** `PacketGuards.MAX_TEXT = 1024`（**两边各写一个上限正是这次事故的根因**）；
  - 上限从 512 提到 **1024**：提示里会拼整合包的物品名，有些模组会往名字里塞
    NBT 后缀 / 属性文本（「钻石剑 +7 锋利 [绑定] …」），比原版名字长好几倍。
    截断的代价（玩家看不到完整信息）比多传几百字节大得多。
- **影响面**：**所有玩家**（这是"提示非空就必掉"）。修完提示超长最坏只是显示不全。

## 二、回收页

- **只卖回收栏里的东西**：以前会把**背包里同类**的物品一起卖掉，
  现在**只看回收栏那 18 格**，背包一件都不动。
  - ⚠️ 与「负债自动还债」**口径不同**：负债时系统**仍然会扫背包**变卖（那是还债，不是玩家主动回收）。
- **明细写清单价与小计**：每行三列 —— 「物品 ×件数 / **单价** / **小计**」，
  单价与小计用**小号点阵字体**、右对齐，小数部分更暗（和持仓表格一致）。
  - 修掉一个显示 bug：以前三种不同物品只要**件数相同**，单价与小计会显示成**完全一样**的数字
    （那是"均价"被当成了"单价"）。现在每一行取**它自己的**单价、乘**它自己的**件数。
- **合计块**：改成「**合计 N 种 · M 件 · 总价 X**」（补上了**件数**，才能和明细对上）；
  有估不出价的东西时，第二行会写「不值钱 N 件」。
- **回收按钮**：显示总额并带上单位（「回 收 1728.00 金币」）。
- **全新装备可以回收，用过的不能**：
  - **未使用过**（一点耐久都没掉）的工具 / 武器 / 护甲**可以卖**，按满价
    —— 一把刚做出来的钻石剑本身就等于一堆材料；
  - **用过的**（掉了哪怕 1 点耐久）**不收** —— 否则就是把工具白用一场再按新价卖回去；
  - 交易所终端本身也不收（它是打开这个界面的钥匙）；
  - ⚠️ **负债自动还债更严**：**任何有耐久的装备都不会被自动变卖（包括全新的）**
    —— 那是系统未经你同意的变卖，宁可少还一点债，也不动你没用过的家当。
- **全屏 / 小窗口下明细文字压在边框上** —— 已修。这是**分辨率相关**的 bug：
  1920×1080 全屏 + GUI 缩放 4 时逻辑分辨率是 **480×270**，明细框会被压成**只有一行高**，
  文字正好填满、上下边框压在字上。现在明细框**至少留出上下内缩**才允许画内容
  （挤不下就整块不画，而不是画一个压线的框）。实测 **6 种宽度 × 165 种高度 = 990 档，
  文字净空全部 ≥2px**。

## 三、行情页

- **买入按钮改红、卖出按钮改绿**（与 A 股「红涨绿跌」一致）。
  颜色是**图集里画好的贴图**（暗底 + 亮描边，悬停提亮一档、按下再压暗），
  不是给灰色按钮染色的 —— 染色是乘法，灰底乘红色会发浑。文字仍是近白色，对比度 5.0~11.6:1。
- **页签高亮修复**：以前三个页签外观一模一样（选中态被按钮皮肤盖住），现在活动页签有明确高亮。
- **持仓表格**：
  - 表格上端上移，能多显示 1~2 行；
  - 数字改为**左对齐**（和列名对齐、正负号成一条竖线）；
  - 表头与行底的分隔线不再压在文字上（净空 ≥2px）。
- **资金块**：删掉重复的「余额」行（顶部标题栏已有），改成「**扛风险 ±x.xx%**」
  —— 当前杠杆下价格反向走多少会爆仓（`50% ÷ 杠杆`），随杠杆输入实时变化。
- **图下说明文字**全部删除（按你的要求"只保留状态词，教程里写"），只留
  「暂无持仓」「暂无明细」这类**状态**词。

- **搜索能用了**：以前搜索框走的是"只收数字"的输入框路径，字母进去也画不出来
  （小号字体图集里**没有字母**）。现在搜索框用普通字体、可输入任意字符。

- 悬停提示保留「单价 / 一组价」两行。

## 五、经济数值回调（设计口径）

| 项目 | 数值 | 说明 |
|---|---|---|
| 手续费 | **0.20%**（往返 **0.40%**） | 单边收取 |
| 购买加价 | **×1.18** | 回收价 ×1.18 = 买价，买完立刻卖回亏 18% |
| 爆仓线 | **45%** | 保证金亏掉 45% 触发强平 |
| 均值回归 | 0.020 | 每跳向基准回归的强度 |

- **新闻不再带涨跌数字**（去方向化）：新闻只讲"发生了什么"，不再预告涨还是跌。
- **估值按稀有度重做**：通用可再生物品**一律 ≤30 金币**
  （蘑菇、鸡蛋、农作物这类可无限刷的不会被高估），
  稀有条目（钻石 300、下界合金碎片 450、鞘翅 3000…）拉开档位；
  估值来源是**数据包种子 + 配方推导**，"劳动换钱"这条路没被削弱。

## 七、已知限制

1. **GUI 缩放 4（逻辑 480×270）下内容较挤**：回收页在那一档只有 1 行回收栏、
   明细约 4 行。文字不再压边框了，但信息量就是有限 —— 想要更宽松就把 GUI 缩放调小
   （设置 → 视频设置 → GUI 缩放）。
2. **精采矿石方块无价**：精准采集挖下来的**矿石方块**（不是矿物本身）推不出估价，
   放进回收栏也是 0 金币、会留在栏里。用带精准采集的镐挖矿石请直接留着或另作他用。
3. **服务端与客户端必须同版本**：这一版给 `S2CSlotValue`（回收栏单价）与
   `S2CStockSnapshot` **加了字段**。旧客户端连新服务端（或反过来）会因为解码失败而掉线 ——
   更新时请**两端一起换**。
4. **`docs/review/` 里的历史截图已经和当前界面不一致**（那是逐版评审留下的记录，不随代码更新）。
